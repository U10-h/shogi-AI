# 中飛車研究室 / shogi-AI

将棋ウォーズ10分切れ負け2級から初段、その先を目指すための個人用将棋練習アプリ。POCO F6 Proのブラウザを主な対象とし、ゴキゲン中飛車の学習を重視します。

## 今できること

- **先生が見守る対局**：指している間に候補と応手を調べ、形勢を損ねた可能性を再確認したときに短く知らせます。毎手は止めません。
- 考えている間に調べた局面は再利用。相手の対局用エンジンと見守り用エンジンは別々に動きます。
- 「先生と確認」を押したときに時計を停止。見つかった一手の意図・次の応手・指し直しを、短い会話で考えます。
- 一緒に確認した手の講評と狙いを40件まで保存。過去の一手の相談も再開できます。
- ブラウザ内のやねうら王NNUEと対局。外部AIのAPIキー・従量料金は不要です。
- 10分の学習モード、助言を隠す実戦モード、時間無制限。
- 思考時間を1 / 3 / 5 / 10 / 30秒から選択。
- 候補手を最大3手比較し、読み筋の盤面を一手ずつ再生。
- 検討盤で両側の手を自由に変更し、再解析・変化保存。本対局の棋譜とは分離。
- 対話で候補手を指定・比較。最善手の理由、相手の反論、想定応手の解析、時間を増やした深掘り。
- 選んだ読み筋の2手先から継続相談。「嬉しい展開・困る展開」の材料を盤面で比べ、予想メモを残して前の相談へ戻れます。
- 精読：候補を広く探した後、候補ごとの重点探索と相手の応手を固定した再確認。候補の入れ替わり・評価の揺れも表示。
- 先生・読み筋・棋譜をタブで切り替え、読み筋は1本ずつ表示。設定と長い説明は必要なときに開けます。
- 任意の端末内日本語対話モデル（Qwen2.5）による質問に合わせた補足。
- 待った、盤面反転、成り・不成、持ち駒、投了、詰み・千日手・連続王手の千日手、27点法の入玉宣言。
- 平手または後手ゴキゲン中飛車の出だし6手から開始。
- KIF/KI2・CSA・USI・SFENの読み込み、KIFの保存、対局と変化を含むJSONバックアップ。
- 同じブラウザで対局を自動保存し、過去20局を保持。

指導対局版0.6です。普段は対局を進め、先生が気になる手を見つけたときに短く知らせます。指摘が出ても時計や対局は止まりません。自分から「先生と確認」を押すと、解析済みの結果を開いて一緒に考えられます。従来の手動検討は「自分で候補を相談する・詳しく調べる」に残しています。使い方と制約は [docs/COACH.md](docs/COACH.md)。弱点の自動診断・画像認識は未実装です。

## 使い始める

1. HTTPSの利用ページをAndroidのChromeで開きます。初回は準備のため一度再読み込みされることがあります。
2. 「設定」で開始局面と「先生と学ぶ」を選び、「先生と対局を始める」を押します。
3. 自分の駒、移動先の順にタップして実際に指します。持ち駒も同じ操作です。
4. 対局はそのまま進みます。気になる手が見つかると「○手目が気になります」と表示されます。先生の欄には短い理由が出ます。
5. 「先生と確認」を押すと時計が止まります。指した理由を答えたり、相手の応手や2手先の局面を質問します。解析済みの講評はそのまま使います。
6. 「本対局を続ける」で中断した盤面に戻ります。「○手目の前から指し直す」なら、その手以降を保存したうえで選び直します。

設定の「対局中に先生が見守る」を外すと、見守りを休止できます。手動の相談は引き続き使えます。詳しく相談するときの探索時間は設定値に従い、複数回探索するため合計時間は長くなる場合があります。

後手ゴキゲン中飛車の出だしは `▲7六歩 △3四歩 ▲2六歩 △5四歩 ▲2五歩 △5二飛` です。その後の相手の戦法は固定しません。先手中飛車は平手から自分で組めます。

棋譜を持っていなくても使えます。読み込んだ棋譜はまず検討盤に開きます。JSONバックアップは対局を復元します。KIFは表示中の一本の手順を保存し、対局結果はコメントに記録します。分岐・時計・履歴を残す場合はバックアップを使ってください。

## 動作条件と制約

- 先生の標準解説は、盤面の事実とエンジンの読みから一つの論点を選んだ短い説明です。評価値や全変化の一覧は「読み筋」に置きます。「攻めたい」「受けたい」などの選択に応じた説明はできますが、自由な文章の意図を意味まで汲み取る補足には任意の言語モデルが必要です。人間の指導者と同じ理解力があるとは扱いません。
- 見守りの各探索は1〜1.5秒、気になる手の再確認は2〜3秒です。直近の待ち行列は最大2手、解析キャッシュは16件。速く進んだ場合は新しい局面を優先し、4手を超えて古くなった解析結果は指摘に使いません。すべての悪手を即座に検出する保証はありません。
- 講評では、最善候補と指した手の差が200点以上のときなどに同条件で読み直します。判定が変わった場合は未確定とし、厳しい局面で抵抗した手を単純に悪手としません。短い読み筋中の駒取りや王手だけで善悪を決めません。

- 初期エンジンは `yaneuraou.wasm@0.1.2` / やねうら王 NNUE KP256 6.03。軽量な2019年の評価関数です。現代の最上位エンジンではありません。アマ名人級という最終目標は未達成・未検証として扱います。
- WebAssembly SIMD、threads、SharedArrayBufferに対応するブラウザとHTTPSが必要です。対局用は探索1スレッド・ハッシュ32MiB、見守り用は別のエンジンで1スレッド・16MiBです。実際のメモリ消費はこれより多く、同時実行では発熱や電池消費が増える可能性があります。
- POCO F6 Proの実機では未検証です。起動、発熱、長時間対局、バックグラウンド復帰、棋力を実機で確認してから性能値を記録します。
- 本体と評価関数は同梱。対局内容を外部AIへ送信しません。初回のページ取得・認証には通信が必要です。キャッシュの削除やホストの認証状態によりオフライン起動できない場合があります。
- データはブラウザ内のみ。端末間の同期はありません。シークレットモードやブラウザのデータ削除で失われます。
- AIは指定時間に近い長さで探索しますが、初期化・表示更新・端末負荷の時間は別です。実戦モードでも手動の一時停止は可能で、公式対局の時間管理を完全再現するものではありません。
- 評価値は解析開始局面の手番側から見た値です。MultiPVの探索深さや評価は時間によって変動します。評価値を勝率に換算しません。
- 「狙いが通る例」は探索した相手の候補内で評価が改善する場合のみ表示します。広い応手集合の探索、定跡知識、指導品質の実機評価は今後の課題です。
- 精読は探索の進め方を強化したものです。評価関数・対局用エンジンのバイナリは従来と同じで、対局勝率や段位の改善は測定していません。相手の全ての応手を網羅するものではありません。
- 精読の追加探索は基準時間の2倍（1探索30秒上限）。基準3秒なら全体の目安は約42〜60秒に準備時間を加えた長さです。取得候補数と終局によって短くなる場合があります。中止すると、途中の比較を新しい結論として採用しません。
- 嬉しい・困る展開は対局設定の自分側から見た、最大10手の読み筋内の観察材料です。駒取り・成り・王手・大駒の筋と単純な駒の収支から抽出し、勝敗や手の良さの証明には使いません。予想メモを文章の意味に合わせて検討する補足には、任意の対話モデルが必要です。
- 自由な日本語対話にはWebGPUと初回のモデルダウンロードが必要です。対応しない端末では、将棋エンジンの解析解説と読み筋比較を使います。言語モデルによる実際の生成は開発環境では未検証です。

## 開発

Node.js 24以降。外部パッケージのインストールは不要です。

```sh
npm run check
npm test
npm run test:engine
npm start
```

ローカルPCでは `http://localhost:4173`。別端末からLANのHTTPアドレスで開く場合はセキュアコンテキストにならないため、HTTPSで提供してください。

`dist/` がそのまま配信可能な静的アプリです。`dist/_headers` にCOOP/COEPを定義し、Service Workerでも同じヘッダーを付けます。HTTPSでのService Workerの動作を維持してください。サイト管理用の `.openai/hosting.json` は既存プロジェクトに対応しており、別のサイトを作るために流用しないでください。

`vendor/tsshogi/src` の固定版をNodeのTypeScript変換で `dist/vendor/tsshogi` に生成しています。再生成は `npm run vendor`。エンジンの出所と改変箇所は [THIRD_PARTY.md](THIRD_PARTY.md) を参照してください。

## 検証

2026-09-19の開発環境で実施:

- 指導対局の実アプリ制御を決定的なエンジン入力で検証: 見守りが未完了でも相手が指すこと、指摘中も時計が動くこと、解析済み講評の再利用、指定応手と2手先の相談、過去の一手からの指し直し、相談中の再読み込み、新しい対局での古い解析破棄、実戦では見守りをしないこと。
- 見守りの自動検証: 先読み結果の再利用、再確認後にのみ指摘すること、速い指し手の待ち行列の上限、無効化・失敗後に解析が走り続けないこと。
- 実NNUEを2つ同時に動かし、一方の対局応手と他方の講評が異なる局面を正しく解析することを確認。日本語の短い講評と意図に応じた回答も確認。
- ルール・棋譜の自動テスト: 初期合法手数、捕獲、二歩、行き所のない駒、強制成り、打ち歩詰め、自玉の王手、千日手、KIF/JSON復元、解析行の検証。
- 同梱WASMをNodeで実行: NNUE初期化、合法な応手、MultiPV 3、合法な読み筋、停止後の再探索、候補手比較、相手の想定応手、2手先からの継続解析、根拠付きの解説。
- ブラウザ操作: 手動検討、変化保存、本対局への復帰、対話用の候補手選択、不正な候補への応答、相談局面の切り替えとメモの復元。
- コントローラーの自動検証: 2手→さらに2手の相談、戻る操作での候補・会話・予想の復元、解析に渡す局面、未検証の予想の引き継ぎ。本対局を変更しないことも確認。
- 精読の自動検証: 候補間の同一時間・同一設定での比較、候補の順位変更、応手固定の評価視点、評価の矛盾、詰み手数の順位、初期化中の中止。実NNUEでも候補の重点探索と応手の再確認を実行。
- 整理後のブラウザ操作: 3つの表示の切り替え、キーボード操作、設定、候補手選択。読み筋を1本ずつ表示するコントローラーも自動検証。
- 開発用ブラウザのプレビューはHTTPで、SharedArrayBufferを利用できません。HTTPS上のブラウザでのAI対局全体とPOCO実機の確認は未完了です。Nodeのエンジン検証とは区別しています。
- WebMCPの任意の読み取りツールを登録する実装がありますが、対応する実行環境での検証は未実施です。通常の操作には不要です。
