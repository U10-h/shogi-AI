# 開発方針

## ゴール

10分切れ負けで初段を目指し、さらに強くなれる指導AIにする。ユーザーはゴキゲン中飛車党。主な課題は、膠着時の方針、無理攻めの判別、受けの読み、序盤の定跡、局面判断。

「最善手を表示する」だけでなく、自分の候補手に対して、狙いが通る例と、相手が正しく咎める例を盤面で比較できることを中心に据える。

## 責務を分ける

| 部分 | 判断すること | 現在 |
|---|---|---|
| 将棋ルール | 合法手、盤面更新、千日手、入玉宣言 | tsshogiを固定版で同梱 |
| 将棋エンジン | 候補手、評価、具体的な読み筋 | ローカルWASMのやねうら王NNUE |
| 指導ロジック | 比較すべき局面、失敗と成功の枝、ヒントの段階 | 候補比較・反論・想定応手・2手先からの継続相談・展開の観察材料と予想メモ |
| 言語モデル | 根拠のある自然な日本語の説明と質問への応答 | WebLLM + Qwen2.5を任意で接続。実機生成・品質は未検証 |
| 学習履歴 | 対局・候補手・誤り・復習間隔 | 対局と変化の端末内保存まで |

言語モデルを将棋エンジンの代わりにしない。生成された指し手は必ずルールで検証し、評価や反論はエンジン結果と結び付ける。「受けがない」「必ず勝つ」など、有限時間の探索で証明できていないことを断定しない。

## 実装順

### 1. 指して使える土台 — 初期版

AI対局、10分時計、開始局面、待った、自動保存。候補手3つ、読み筋再生、手動で応手を変更する検討盤まで実装する。

初期エンジンは軽量な既存WASMで開始。最終棋力の要件を満たしたとは扱わない。POCO F6 Proで1/3/10秒の探索、初回起動、メモリ、発熱、10分の対局継続を測定する。次のエンジンに差し替えられるようUSIの境界を保つ。

### 2. 対局画面内の指導

0.2では下記1〜4の基本比較と6の端末内モデル接続を実装。詳細は[COACH.md](COACH.md)。比較する応手は現状MultiPV 3に限定し、定跡知識と説明品質の実機評価は引き続き必要。

0.3では、各読み筋から2手先へ進んだ局面を新しい相談の基準にし、元の相談へ戻って枝を比較する操作を追加。嬉しい展開・困る展開を予想してから、合法な読み筋の観察材料と照らし合わせる。予想の自動採点、静かな局面の長期方針の十分な説明、継続的な学習履歴は今後の課題。

1. 任意の候補手を選択して「この手をどう思う？」と質問できるようにする。
2. 同じ初期局面から候補手を固定して探索し、最善の応手を返す枝を作る。
3. 別の自然な応手を固定した枝も探索し、狙いが通る成功例を作る。成功例には「相手がこの対応をした場合」と明示する。実際の相手がその手を指す確率は、データなしに表示しない。
4. 候補ごとに、最善に応じられたときの損失、成立条件、反撃、駒損と代償を分ける。「罠」は最善応手に弱い手なのか、実用的にも許容できる手なのかを区別する。
5. ゴキゲン中飛車の代表的な分岐、攻めを始める条件、囲いを整える手、相手の攻めへの備えを、検証した局面と出典付きの自作解説で蓄積する。
6. 画面内の日本語対話を接続する。無料優先で小型ローカル言語モデルのWebGPU実装を実機測定する。性能不足ならPC上のローカル推論を候補にし、有料APIを必須にしない。

ヒントは「相手の狙い」→「注目する駒・筋」→「候補」→「具体的な手順」の順で開示。ユーザーが先に自分の手と読みを入力できるようにする。盤面を動かす・候補を切り替える・質問する操作を対局画面内で完結させる。

言語モデルへ渡す情報は、局面、指し手、同じ根の評価、探索時間・深さ、検証済みの枝、駒の収支、出典のある解説。戻り値は要点、成立条件、反論、参照する枝、確実性の構造を持つ。根拠と一致しない説明は表示を抑制する。

### 3. 継続指導

実戦での誤りと助言を使った局面を区別して記録する。「無理攻め」「受けの見落とし」「序盤の分岐」「膠着時の方針」を、候補と反証付きで復習問題にする。短期の評価値の揺れだけで弱点を断定しない。少数局の傾向は仮説として扱う。

10分実戦モードと、時計を止めて考える学習モードを往復する。まずユーザー自身の読みを残し、何手先で想定と分かれたかを復習する。履歴が増えたらIndexedDBへ移行し、JSONの移行機能を維持する。

### 4. 精度・入力・棋力の強化

- 新しいNNUE/WASMへの交換、探索時間とMultiPVの調整、必要ならPC推論を追加。
- 実機上で参照エンジンとの固定条件対局と戦術問題を測り、指導の検証用エンジンとして十分か判断。人間の段位との対応は単純換算しない。
- スクリーンショット・写真の認識。駒の向き、持ち駒、成駒、手番を認識後にユーザーが確認・修正してから解析する。画像だけでは分からない千日手履歴を創作しない。
- 将棋ウォーズ・ぴよ将棋の実際の出力例で棋譜互換性を拡充。
