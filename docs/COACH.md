# 対話で検討する

## 操作

1. 学習モードで、相談したい盤面を表示します。
2. 「盤面で候補を選ぶ」→駒→移動先、の順で候補を指定します。本対局にはまだ指しません。
3. 「質問する」を押します。「角道を開けたい」「受けを先にしたい」など自分の狙いも添えられます。
4. 最善候補との評価差と、相手の応手を含む手順を確認します。手順のボタンで対応する盤面を開けます。
5. 「最善手の理由」「相手の反論」「狙いが通る例」「もっと深く」で続けて検討します。
6. 読み筋の「この2手の先を相談」で、手番側の一手と相手の応手を進めます。次の候補を選んで、その局面から相談を続けられます。
7. 「先の展開を自分で考える」に、実現したいこと・避けたいことを予想として書きます。「予想と読み筋を比べる」で具体的な盤面と照らし合わせます。
8. 「一つ前の相談へ」で前の局面・候補・会話・予想に戻り、別の応手を選んで比べられます。

文字入力では `7六歩はどう？`、`７六歩`、`7g7f` に対応します。同じ表記の手が複数ある場合は候補から選びます。`5八金右` や `5八金(69)` のような指定もできます。

自分の候補を選んだ後、`相手が3四歩なら？` のように相手の手を指定すると、その応手を固定して再解析します。指定する手は候補を指した後の局面で合法である必要があります。

相談の基準局面は固定されます。読み筋の各手を表示するだけでは質問の対象は変わりません。「この2手の先を相談」では盤面と相談の基準を一緒に進めます。任意の局面に進めた場合は「表示局面で相談」で切り替えられます。本対局の棋譜は変更しません。

`2手先では？` と入力しても、どの読み筋へ進むかを選べます。2手は2回の着手です（自分の手と相手の応手）。同じ操作を繰り返して4手先・6手先へ掘り下げられます。前の局面で書いた予想は未検証の予想として会話に引き継ぎます。戻る履歴は直近24局面を保持し、新しい対局に切り替えるとリセットします。

## 嬉しい展開と困る展開

「ここから何を目指す？」「嬉しい展開と困る展開は？」にも対応します。各読み筋に、対局設定の自分側から見た材料を表示します。相談の途中で相手番になっても、この立場は変えません。評価値は従来どおり相談の基準局面の手番側から見た値なので、表示される側を確認してください。

- 最大10手の合法な読み筋から、駒取り・取り返し・成り・王手・飛車と角の筋・単純な駒の収支を集計します。
- 材料ごとの「○手先の盤面を見る」で、その変化が起きる盤面を開けます。
- 同じ基準局面のMultiPVで評価が100点以上低い別候補が得られた場合は、その読み筋も比較用に表示します。劣る展開を見せるために未解析の手順を創作しません。
- 駒取りや王手は好手の証明ではなく、駒を犠牲にする手も悪手の証明ではありません。取り返しや玉の安全、相手の反論とセットで検討します。
- 材料が抽出できない場合は未確認と表示します。危険がない、狙いがないとは扱いません。

予想メモは空欄でも使えます。端末内の日本語対話モデルを有効にしている場合は、予想を検証済みの根拠と分けて渡し、質問に合わせた補足を求めます。有効でない場合も具体的な読み筋と観察材料は表示しますが、自由文の意味を理解して正誤判定する機能ではありません。

## 解析の組み立て

- 基準局面でMultiPV 3を探索して最善候補を選びます。
- 自分の候補を指した後の局面で、相手の応手をMultiPV 3で探索します。
- 最善候補が異なるときは、その手の後も同じ時間・MultiPVで探索します。
- 相手番の評価値を反転し、常に相談した側から見た値にそろえます。詰み手数は一手分補正します。
- 「相手が別の応手を選んだ例」は、取得した応手の中で相談した側の評価が100点以上改善するものがあれば表示します。成功の保証や、相手が選ぶ確率は示しません。
- 想定する相手の手が指定されたときは、その2手を固定した後を探索します。
- 「もっと深く」は各探索の時間を増やします（最大30秒）。一つの相談では通常2〜3回、想定応手があれば最大4回探索するため、合計時間は設定値より長くなります。

比較した評価は異なる探索の結果であり、厳密な損失の証明ではありません。追加解析でユーザーの候補が上回った場合は結論の揺れとして説明します。詰み・境界値を通常の評価値から引き算しません。

## 二つの説明方法

**解析解説**は追加ダウンロード不要です。評価差、王手、捕獲、成り、大駒の筋、玉の周囲、読み筋中の具体的な駒取りを盤面から集計して説明します。エンジンの評価関数の判断理由を完全に復元するものではありません。

**自由な日本語対話**は「日本語対話を有効にする」で追加できます。WebGPU対応のブラウザでQwen2.5 0.5Bまたは1.5Bをダウンロードし、端末内で動かします。WebLLM 0.2.85を利用し、GPUが対応していればfloat16、そうでなければfloat32のモデルを選びます。

モデルへは現在の質問、直近の会話、将棋エンジンの解析から抽出した根拠を渡します。棋譜・質問を外部のAI推論APIへ送る実装はありません。初回はCDN・Hugging Face等からライブラリとモデルを取得します。小型モデルのため説明の誤りは残り得ます。

補足には根拠IDを必須とし、根拠にない指し手・評価値・強い勝利の断定が含まれる場合は表示を抑制します。この検査は自然言語の全ての誤りを検出するものではありません。元の解析結果を常に残し、モデルの説明で上書きしません。

相談履歴はページを開いている間保持します。現時点では対話の長期保存・弱点の自動診断は未実装です。盤面の変化は従来の「変化を保存」で保持できます。

## 検証範囲

- 日本語/USI入力、曖昧な手、合法性、評価の視点、詰み手数補正、比較と想定応手、キャンセル、説明の根拠チェックを自動検証。
- 実際の同梱NNUEで候補比較・想定応手の探索・読み筋合法性・解説生成を確認。
- 実NNUEで2手先からの再探索を確認。自動テストで複数回の継続相談、相談と予想の復元、評価・観察の立場、駒取りと取り返し、材料のない読み筋を検証。
- ブラウザで候補指定が本対局を変更しないこと、不正な候補への応答、表示局面の相談への切り替え、戻る操作での盤面・予想の復元を確認。
- 開発プレビューはHTTPのため、ブラウザのWASMスレッド・WebGPU生成の全体動作は未検証。POCO F6 Proでの速度、メモリ使用、モデルの日本語品質は実機検証が必要です。
