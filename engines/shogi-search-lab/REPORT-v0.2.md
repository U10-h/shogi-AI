# 第2回：反復深化を追加し、読みの検証を採用条件にする

実行日：2026-09-21。ユーザー方針は「時間内に深く読むことを優先し、正しく読めているかの確認を必須にする」。
今回は、反復深化、前回の読み筋の優先、探索全体に共通する時間・局面数の上限を実装しました。評価関数と合法手生成は前回から変更していません。

## 実装した動作

深さ1、2、3…と順に探索し、前の深さで得た最善の読み筋（PV）の手を優先します。優先するのは根から同じ手順をたどった局面だけです。評価値はその深さで改めて計算します。
途中で時間・局面数の上限に達した場合は、その反復を破棄し、最後まで読み終えた深さの評価と読み筋を返します。根の候補手を途中まで調べた値は採用しません。
`depth`は目標、`completed_depth`は実際の到達深さです。`complete:false`でも`has_result:true`なら完了済みの浅い結果があります。最初の1手も完了しなければ評価・最善手はnullです。

## 正しさの検証と確認できた範囲

| 検査 | 結果 | 確認対象 |
|---|---|---|
| C++テスト | 115項目合格 | 従来のルール、各深さの結果、中断時の復元、千日手、連続王手、模擬時計による時間切れ |
| 全幅探索との照合 | 8局面×深さ1〜3×2方式＝48回、一致 | PV優先あり／なし、各反復の評価値 |
| 少し深い全幅探索 | 初期局面の深さ4、746,132ノードとの一致 | 最終評価と選ばれた読み筋 |
| 読み筋途中の最適性 | 上記の各完了結果で合格 | PVの各途中局面も全幅探索し、根の値を維持できるか |
| 独立実装との照合 | 9局面、一致 | tsshogiの合法手＋独立した先手max／後手minの全幅探索、駒得評価、PVの合法性と末端評価 |
| 詰みの具体例 | 1手詰めを+99,999、詰まされた局面を−100,000と判定 | 詰みを通常の駒得と混同しないか |
| 探索木のPV優先 | 283ノードのログ、6か所の優先を確認 | 別の手順へ前のPVを流用せず、対象手を最初に読んでいるか |

独立実装の9局面は深さ2を中心とする小規模照合で、千日手は別途C++の履歴テストで検証しています。深い全局面を独立に証明したものではありません。
全幅探索との一致が示すのは、同じ深さ・同じ評価関数に対して探索計算が一致したことです。将棋としての評価精度や棋力は別に検証する必要があります。

## 同じ深さ4での比較

前回と同じ8局面を使用しました。各方式を1回予備実行後、順番を交代して3回ずつ逐次実行。表の時間は中央値です。反復深化は浅い探索も含めた合計で比較します。

| 局面 | 直接深さ4：局面数 | 反復のみ：局面数 | 反復＋PV優先：局面数 | 直接→反復＋PVの時間 ms |
|---|---:|---:|---:|---:|
| initial | 8,656 | 9,837 | 4,272 | 17.604 → 13.197 |
| gokigen-6 | 4,198 | 5,952 | 5,952 | 21.489 → 31.294 |
| gokigen-20 | 12,199 | 13,994 | 13,902 | 47.383 → 57.103 |
| gokigen-36 | 490,747 | 497,650 | 490,379 | 1106.559 → 1142.835 |
| gokigen-52 | 75,091 | 82,262 | 47,619 | 246.305 → 216.788 |
| bishop-exchange | 111,224 | 117,815 | 24,665 | 220.452 → 81.234 |
| pin-and-drop | 3,748 | 4,914 | 4,699 | 10.103 → 11.151 |
| promotion | 174 | 283 | 283 | 0.282 → 0.354 |

8局面の合計は 706,037 → 591,771 ノード（16.2%減）。各局面の時間中央値の合計は 1670.177 → 1553.956 msでした。直接深さ4と比べ、局面数は4/8局面、時間は3/8局面で改善しました。
最終評価は8局面で3方式すべて一致しています。代表例の角交換では111,224→24,665ノードに減りました。初期局面も8,656→4,272ノードに減りました。
一方、gokigen-6やpromotionでは、最終反復の探索木が変わらず、浅い探索の追加分だけ訪問数が増えました。gokigen-36は訪問数がわずかに減りましたが、時間中央値は増えています。局面数と時間を別々に見る必要があります。
これらの原因として、前の深さの手順が次の深さでも役立つか、もともとの駒取り優先が十分に機能しているか、並べ替えと反復の負担が削減分を上回るかが考えられます。原因の切り分けは次の実験課題です。

## 200msでどこまで読み終えたか

反復のみと反復＋PV優先を、各3回・上限200ms・目標深さ8で比較しました。双方とも浅い完了結果を返せる方式です。表は3回それぞれの完了深さです。
時間は探索部分のみ。プロセス起動・盤面初期化を除き、途中で中断した反復も含めています。

| 局面 | 反復のみ | 反復＋PV優先 |
|---|---|---|
| initial | 4, 4, 4 | 4, 4, 4 |
| gokigen-6 | 4, 5, 5 | 5, 5, 5 |
| gokigen-20 | 4, 4, 4 | 4, 4, 4 |
| gokigen-36 | 3, 3, 3 | 3, 3, 3 |
| gokigen-52 | 3, 3, 3 | 3, 4, 3 |
| bishop-exchange | 3, 3, 3 | 4, 4, 4 |
| pin-and-drop | 5, 5, 5 | 5, 5, 5 |
| promotion | 8, 8, 8 | 8, 8, 8 |

角交換ではPV優先によって3回とも3手から4手へ進みました。gokigen-52はPV優先でも4手に到達したのは1/3回で、安定した改善とは判断しません。
全48回で完了済みの結果を返し、その読み筋を合法に再生できました。各結果は、実際の完了深さと同じ固定深さαβ探索の評価とも一致しています。この深い照合は全幅探索ではありません。最大実測時間は200.896msでした。
各ノード入口での時間検査なので、処理中の1ノードやOSの割込みによる超過があり得ます。厳密な時間保証ではありません。ノード上限2,000万にも共通で従います。

## 取り返しを読めたか

5四の後手歩を5三の金が守り、先手飛車が5五にいる局面では、深さ1の `5e5d` が+550点でした。
相手の応手まで読むと `5c5d` で飛車を取られ、先手から−1,450点になります。深さ2の完了結果はこの候補を退け、`5e1e` を+350点と評価しました。
反復途中の候補が深さを増やしたことで修正されることを、独立実装でも確認しています。ただし、固定した深さの直後に取り返しが起きる問題は引き続き残ります。静止探索は未実装です。

## 今回の判断と次の研究

反復深化は、いつ止まっても完了した読みを残す基盤として採用します。PV優先は切替可能にして、効果がない局面も比較できるようにします。全局面で高速化したという結論にはしません。
次は速度が改善しなかった局面の木を調べ、PV以外の有力手をどう先に読むかを研究します。前の探索の情報を増やす場合も、評価の境界値と確定値を区別し、正しさの照合を続けます。
将来的な置換表では千日手履歴や詰みまでの距離を含む値の扱いが課題になります。今回の実装は過去の評価値を再利用しないため、その問題を持ち込みません。
