# v1.0 研究方針 — YaneuraOu-compatible Learned Selective Search

更新日: 2026-09-27

## 1. 背景

v0.16 まで、Shogi Search Lab では αβ探索、手順序付け、LMR、学習型枝刈り、評価関数補正、候補保持、選択的な探索深度配分などを段階的に実装・検証してきた。

v0.16 では、深さや候補数を固定せず枝ごとに探索費用を変える方式を実装し、双方1手1秒の条件でやねうら王との16対局を実施した。最大到達手数や一部の着手指標には改善が見られた一方、各設定0勝4敗であり、終盤には初回反復が時間内に完了しない局面も確認された。

この結果から、現在の「自作探索 + 現在の評価基盤」をそのまま微調整し続けるだけでは、やねうら王との差の原因を切り分けにくい。探索そのものの良し悪しと、評価関数・盤面表現・実装最適化・定跡などの差が混在しているためである。

v1.0 では研究設計を変更し、**強い既存基盤を利用して評価能力をできるだけ揃え、その上で探索アルゴリズムの差を測る**。

---

## 2. v1.0 の中心課題

中心課題は次の2点とする。

1. **同一または可能な限り近い評価基盤で、自作探索とやねうら王探索を比較する**
2. **「どの枝に計算資源を配るべきか」を学習し、同等品質の着手をより少ない探索ノードで発見する**

最終的に直接対局でやねうら王を上回ることは長期目標として残すが、研究上の主要指標を勝敗だけに置かない。

特に重視する問いは以下である。

> やねうら王と同等の評価基盤を与えたとき、独自の選択的探索は、どれだけ少ない計算量で有力手を発見できるか。

---

## 3. 設計方針

### 3.1 ゼロから全要素を再実装しない

合法手生成、盤面表現、評価関数、NNUE の推論など、探索研究そのものではない基盤部分は既存実装の利用を認める。

候補として、やねうら王側の独自エンジン差し替え機構（USER_ENGINE 等）を利用し、以下を可能にする構成を技術検証する。

- 共通の盤面表現
- 共通または同一の NNUE / 評価関数
- 共通の合法手生成
- 自作の探索ロジック
- やねうら王標準探索

これにより、比較対象を可能な限り「探索の違い」に近づける。

### 3.2 研究対象を探索資源配分に絞る

v1.0 で主に独自化する部分は以下とする。

- Move Ordering
- 探索深さの動的配分
- LMR の削減量
- 延長条件
- Futility Pruning
- Late Move Pruning
- 再探索条件
- aspiration window / bound の扱い
- PV候補の保持と再利用
- 時間・ノード予算の動的配分

評価関数そのものの改善は補助研究とし、「探索改善」と混ぜない。

## 4. 最初に行う比較実験

探索と評価の寄与を切り分けるため、少なくとも次の条件を用意する。

| 条件 | 探索 | 評価 |
|---|---|---|
| A | 現在の自作探索 | 現在の評価 |
| B | やねうら王標準探索 | 軽量・単純評価（利用可能なら） |
| C | 自作探索 | やねうら王系NNUE |
| D | やねうら王標準探索 | Cと同じNNUE |
| E | やねうら王標準探索 | 強い標準設定 |

最重要比較は **C vs D** とする。

ここで評価関数、Threads、Hash、持ち時間、定跡使用、ponder、開始局面集合などを可能な限り揃える。

これにより、

- 評価関数の差
- 探索の差
- 実装速度の差
- 時間管理の差

を分けて議論する。

---

## 5. やねうら王を「対戦相手」だけでなく「教師」にする

大量の局面に対して、やねうら王の深い探索結果を教師データとして保存する。

収集候補:

- SFEN
- 合法手一覧
- MultiPV の候補順位
- 各候補の評価値
- PV
- 探索深さ
- seldepth
- nodes
- nps
- hashfull
- 浅い探索時の評価
- 深い探索後の評価
- 最終順位の変化

### 5.1 最初の学習対象

最初から枝を削除する分類器を作らない。

まずは、

> 「この手を先に読むべきか」

を予測する **Move Ordering モデル** から始める。

目標変数の候補:

- 教師の最善手か
- Top-3 に入るか
- 深い探索で α を更新するか
- 深い探索で PV に残るか
- 浅い探索と深い探索で順位が上がるか
- 探索すると大きな cutoff を誘発するか

Move Ordering で効果と安全性を確認した後、探索量の決定へ進む。

## 6. Learned Selective Search

最終的には、各手について

[
P(\text{deep search is valuable} \mid \text{position}, \text{move}, \text{search state})
]

を推定し、固定深さではなく枝ごとに探索費用を変える。

イメージ:

```text
root
├─ move A : high priority  -> deep search
├─ move B : high priority  -> deep search
├─ move C : medium         -> normal search
├─ move D : low            -> reduced search
└─ move E : very low       -> shallow verification
```

ただし、学習モデルの予測だけで重要枝を即座に捨てない。

段階的に、

1. 並べ替えだけ
2. reduction量の調整
3. 再探索条件の調整
4. 保守的な pruning
5. 動的な時間配分

の順に適用する。

---

## 7. 探索における「情報伝搬」の観測

ナースロスタリング研究で扱ってきた制約伝搬の発想を、探索木へ応用する。

着目点は、

> あるノードを読むことで、他のどのノードを読む必要がなくなったか。

である。

αβ探索では、ある枝の評価値によって α / β bound が更新され、兄弟枝や子孫の探索量が変化する。これを単なる cutoff 数として数えるだけでなく、因果関係をログ化する。

### 7.1 探索伝搬グラフ

各探索について次の関係を保存する。

- 親ノード → 子ノード
- 評価値取得ノード → α更新
- 評価値取得ノード → β cutoff
- TT hit → 再探索省略
- history / killer → 手順序変更
- 学習モデル → reduction変更
- shallow search → deep re-search
- PV更新 → 次回反復の手順序変更

例:

```text
N1 の探索
  ↓
alpha 更新
  ↓
N2 の window が狭くなる
  ↓
N2-3 で beta cutoff
  ↓
N2-4 ... N2-20 の探索が不要
```

この「どの探索が何ノード分の後続探索を消したか」を測る。

## 8. 学習したい新しい量

従来は「強そうな手」を予測することが中心だった。

v1.0 では、それに加えて **探索する情報価値** を学習対象にする。

候補指標:

- α更新確率
- β cutoff確率
- PV入り確率
- 深い探索による順位反転確率
- 誤枝刈りリスク
- 追加1000ノードあたりの評価安定度
- その枝を読むことで削減できた後続ノード数
- TTへ有用な情報を残す確率
- 次回 iterative deepening で再利用された度合い

将来的には、

[
Utility(move)
= ExpectedSearchInformationGain(move)
  - \lambda \times SearchCost(move)
]

のような探索優先度を構成する。

## 9. 評価指標

勝敗だけではなく、以下を同時に測る。

### 9.1 対局性能

- やねうら王との勝敗
- 自作旧版との勝敗
- 既存探索手法との勝敗
- 先後交換
- 平均終局手数
- 投了直前評価
- 引き分け / 千日手

### 9.2 着手品質

- 教師最善手一致率
- Top-3一致率
- 教師最善手との差
- blunder率
- PV一致率
- 深い探索での順位反転率

### 9.3 探索効率

- 探索ノード数
- nodes/sec
- 完了深さ
- seldepth
- 1手の実行時間
- cutoff数
- cutoff 1回あたりの削減ノード
- TT hit率
- 再探索回数
- 初回反復未完了率

### 9.4 研究上の最重要指標

特に、

> **同程度の着手品質を得るために必要な探索ノード数**

を主要評価とする。

例:

```text
YaneuraOu : 10,000,000 nodes -> teacher loss X
Our search:  3,000,000 nodes -> teacher loss X
```

のように比較できれば、直接対局の勝率だけでは見えない改善を評価できる。

## 10. 実験プロトコル

比較では条件を固定する。

- 同じ開始局面集合
- 先後交換
- 同一NNUE
- 同一Hash
- 同一Threads
- 同一定跡条件
- 同一ponder条件
- 同一時間制限または同一ノード制限
- seedを使う場合は保存
- 全KIF / SFEN / USIログを保存
- 実行バイナリとcommit hashを保存

時間制限実験とノード制限実験を両方行う。

時間制限では実装速度込みの実用性能を測り、ノード制限では探索アルゴリズム自体の効率を測る。

## 11. v1.0 への実装フェーズ

### Phase 0 — 基盤比較の成立

- やねうら王系の盤面・合法手・NNUEを自作探索から利用できるか技術検証
- 同一局面の静的評価一致テスト
- USI入出力を統一
- 1スレッド・定跡なしの再現可能条件を作る

成功条件:
- C vs D を同一評価で実行できる

### Phase 1 — 素の探索差を測る

現在の v0.15 / v0.16 系探索を新基盤へ移植し、余計な学習を切った状態で比較する。

測るもの:
- nodes
- depth
- seldepth
- nps
- teacher loss
- 対局結果

ここで「評価が弱いから負けている」のか「探索が弱いから負けている」のかを定量化する。

### Phase 2 — 教師データ生成

やねうら王で大量の局面を深く探索し、Move Ordering / α更新 / cutoff / 順位反転の教師データを作る。

学習・開発・評価局面を対局単位で分離し、リークを避ける。

### Phase 3 — Learned Move Ordering

学習モデルは探索順序だけに用いる。

枝刈り条件は変えない。

成功条件:
- 同一深さでノード削減
- 最善手一致率を悪化させない
- 未知局面でも再現する

### Phase 4 — Learned Reduction

LMR の削減量を局面と手ごとに調整する。

安全策:
- 王手
- tactical move
- PV node
- TT move
- 浅い深さ
- mate関連
- 高不確実性

では強い reduction を禁止する。

### Phase 5 — 探索伝搬グラフ

ノード・bound・cutoff・TT・re-search の因果関係を保存し、

- どのノードが多くの探索を節約したか
- どの種類の枝が情報価値を持つか
- どの局面で学習型選択探索が失敗するか

を分析する。

### Phase 6 — Learned Search Utility

「良い手」ではなく、

> 読む価値のある手

を推定し、限られた時間 / ノードを動的に割り当てる。

---

## 12. 安全な改善順序

学習を探索へ入れるときは次の順を守る。

1. ログのみ
2. Move Ordering
3. reduction の微調整
4. extension の調整
5. pruning の閾値調整
6. 枝の省略

いきなり枝を削除すると、教師との一致率が高くても少数の致命的な見落としで棋力が大きく落ちる可能性がある。

全ての新方式に fallback を用意し、「自信がない場合は従来探索へ戻る」構造にする。

---

## 13. v1.0 で目指す成果

最低限の成果:

- 同一NNUE条件で、自作探索とやねうら王探索を比較できる実験基盤
- 探索の詳細ログ
- Move Ordering 学習
- 探索伝搬グラフ
- 再現可能な評価セット

研究として望ましい成果:

- 着手品質を保ちながら探索ノードを有意に削減
- 固定ノード条件でやねうら王標準探索との差を縮小
- 情報伝搬量と有力枝の関係を発見
- 従来の LMR / history heuristic では捉えにくい特徴を特定

長期的な挑戦:

- 同一評価・同一計算条件でやねうら王標準探索を上回る
- その後、より強い評価関数・並列化を加えてフル設定との対局へ進む

---

## 14. やらないこと

v1.0 初期では以下を主目的にしない。

- NNUEそのものをゼロから作り直す
- 合法手生成の独自実装競争
- GUI改善
- 定跡データ量の競争
- 単一の少数対局だけで「強くなった」と判断する
- やねうら王との勝敗だけを唯一の評価にする

研究対象はあくまで **探索と探索空間への計算資源配分** とする。

## 15. 次に実装するもの

最初の実装タスクは以下。

1. やねうら王基盤へ自作探索を載せる方法を技術検証
2. 同一NNUEを用いた C / D 比較の最小構成を作る
3. USIログに nodes / depth / seldepth / score / PV / cutoff統計を追加
4. 固定局面セットで同一ノード比較
5. 先後交換対局
6. 教師データ生成器
7. Move Ordering モデルの最初のベースライン

この段階を **v1.0-alpha** とする。

## 16. 研究上の位置付け

この方針では、「強い将棋AIをゼロから再現する」こと自体を目的にしない。

研究の中心は、

> **探索木における情報伝搬を観測し、その情報から将来の探索価値を予測して、限られた計算資源を有望な枝へ選択的に配分すること**

である。

これはこれまでの Shogi Search Lab で蓄積した選択的探索・学習型枝刈り・候補保持の実験と、制約充足 / 最適化研究で用いてきた「伝搬を観測して探索空間を削減する」という発想を接続する方向である。

v0.x で得られた失敗例も捨てず、学習型探索が危険になる局面を検出するための負例として利用する。
