# Phase 0b — 共通NNUEへの探索接続を2局面で確認

依頼日: 2026-09-27。起点: Phase 0aの `f4e445450418ce392ec4b3d2e360e10bd60efc7c`。

**同じやねうら王実行ファイル内で、標準探索と最小の自作探索を切り替える接続を実装し、2局面・深さ3の確認を完了した。**
全幅minimaxとαβ探索は、両局面で評価値・最善手・PVが一致した。中断時の盤面復元と、同じプロセスでの再探索も確認できた。

今回の目的は接続の正しさの確認であり、棋力改善の実験ではない。既存v0.15探索全体の移植はまだ行っていない。

## 共通化したもの

前回は同じ重みを別実装の推論器で使っていた。今回は固定YaneuraOu 6.03の標準探索入口に差し替え口を追加し、次の部品を実際に共有した。

- `Position`、`StateInfo`、`do_move` / `undo_move`
- 上流の `MoveList<LEGAL_ALL>` による合法手生成
- **上流の `Eval::evaluate` と同じNNUE重み**
- USI、スレッド管理、`do_move` 内のノードカウンタ
- 同じバイナリ、コンパイラ、AVX2/BMI2設定

USIオプション `Phase0Search` で `standard` / `alphabeta` / `minimax` を選択する。既定値は `standard`。
USER_ENGINEマクロ自体は使わず、標準探索の入口から専用関数へ分岐させた。評価器や盤面を別々にビルドする差を避け、標準モードをそのまま対照として残すためである。

実装: [native/phase0b_search.cpp](native/phase0b_search.cpp)。上流ソースへの変更箇所はビルドスクリプトとmanifestに記録した。

## 最小探索の仕様

自作側は、USI文字列の辞書順で全合法手を調べるnegamax。`minimax` はαβカットを無効にした対照で、`alphabeta` はαβカットだけを有効にする。
両者とも反復深化1→2→3を行い、同点時は先に読んだ手を保持する。

- 主探索の葉は同じ上流NNUEで評価する。
- 葉でも合法手がない終局状態を先に判定する。
- 静止探索、TT、LMR、学習、history、延長はまだ入れていない。
- この最小実装は、深さ3・40万ノード・3秒で内部停止する。外部応答待ちは8秒。
- 1スレッド、全合法手、入玉宣言なしで検証した。通常の対局用エンジンとしての使用は想定していない。

NNUEの差分更新を確認する `Phase0Audit=true` では、探索中の `Eval::evaluate` を毎回 `Eval::compute_eval` による全再計算と照合する。
探索終了時には、**探索に使ったPositionそのもの**のSFEN・キー・StateInfoポインタ・差分評価・全再計算評価が、開始時の状態へ戻っているか確認する。

## 2局面・深さ3の結果

局面は前回の初期局面と角交換後の序盤局面。1回のコマンドで新たに実行するのは1局面だけとした。
以下のノード数は、深さ1〜3の反復を合計した上流 `do_move` カウンタである。

| 局面 | 全幅minimax | αβ探索 | 最善手 | 共通評価値（歩=90） |
|---|---:|---:|---|---:|
| 初期局面 | 27,360 | 2,838 | `7g7f` | 317 |
| 角交換後 | 291,698 | 23,974 | `B*5e` | 292 |

**両局面で最善手・評価値・3手のPVが一致した。**
minimaxのノード数は、別の盤面呼出し経路で求めたperftから計算した `3×perft(1) + 2×perft(2) + perft(3)` とも一致した。

αβによるノード削減は、それぞれ89.6%と91.8%。これは既知のαβ法が正しく働くことを確認した結果であり、新しい学習方式の改善率や、やねうら王標準探索に対する削減率ではない。

4回の自作探索（2局面×2方式）中の **345,882回の差分評価／全再計算照合で不一致0**。
静的評価も根と後続手の計6状態について、変更前の標準バイナリと3つの切替設定を照合し、18対応比較すべて一致した。

## 標準探索が変わっていないことの確認

変更前のPhase 0aバイナリと、今回の `standard` 既定設定を、各局面の深さ3で比較した。
2局面とも**評価値、最善手、PV、完了深さ、ノード数が一致**した。
標準探索のノード数は初期局面117、角交換後375だった。

標準探索と今回の最小探索では、静止探索や枝刈りなどの葉の扱いが違う。標準探索は `2g2f` / `6i7h` を選び、自作の最小探索とは異なった。
この相違をバグや棋力差とは判断していない。今回の全幅対照が保証するのは、同じ葉評価・同じ深さでのminimaxとαβの一致である。

## 中断・再開

各局面で次の5種類の制御確認を行った。

1. `go depth 3 nodes 1` で厳密に1ノードで停止し、合法なfallbackを返す。
2. 中断後、positionを送り直さずに深さ3を実行し、通常時と評価値・最善手・PV・ノード数が一致する。
3. 深さ1の出力を受けて `stop` を送り、外部停止を検出し、盤面を復元する。
4. 外部停止後も、同じプロセス・同じ局面で通常時と同じ深さ3探索を再現する。
5. `go infinite nodes 1` で内部停止しても、`stop` 前に `bestmove` を出さない。

全項目が2局面とも通過した。完了済みチェックポイントの再実行は新規0件になった。

## 範囲と限界

- 比較探索8回（2局面×変更前標準・変更後標準・minimax・αβ）、制御確認10回。開発中の深さ1スモーク確認1回は比較集計に含めていない。
- 時間は監査処理を含む。各方式1回だけで、速度評価や統計的な優位性を示す実験ではない。
- 推論・盤面・合法手・ノード計数は共通化できたが、最小探索はまだTTを使わない。Hash設定が同じでも、同じ表を探索に利用した比較にはなっていない。
- 深さ3の裸の葉評価では、駒取りの応酬を途中で打ち切る影響がある。現行自作エンジンの代替にはしない。
- 棋力、教師損失、未知局面、入玉、長手数の千日手処理は今回の検証範囲外。固定の古い6.03/KP256が対象。

## 次の小さなステップ

**同じ2局面のまま、既存探索の限定静止探索を段階移植する。**
まず主探索深さ2・静止探索上限2で、比較する両方式に同じ葉処理を使い、評価一致・盤面復元・中断を再確認する。
接続が安定してからTT、手順序の実験、学習型Move Orderingへ進む。局面数や対局数はまだ増やさない。
