# 第3回：上位5候補の部分木を保持して、着手後に継続する

実行日：2026-09-21。今回の要望は「各盤面の読みを深め、候補の手が指されたらその読みを保持して進める。上位5手は保持する」。
同一プロセス内で探索木を持つ継続モードを追加しました。候補ごとの評価・深さ・読み筋と、探索済みの部分木を保持し、着手後は該当ノードを新しい根にして自動で探索を再開します。

## 実装した保持と継続

- 各分析局面で全合法手を同じ深さで比較し、評価順に上位5候補を確定。同点はUSI文字列順。合法手が5手未満ならすべて保持します。
- 5候補の評価は確定値です。候補ごとに全窓の探索を行い、内部のαβ探索で得た上限・下限と混同しません。
- 5候補の部分木を残し、それ以外の根直下の枝は解放します。次に深く読む際は、保持外の合法手も再び候補として調べます。
- `play`は着手後の根を切り替え、既定200msの追加探索を自動実行します。`advance`は根の切替だけを行い、引継ぎ直後を観察する操作です。
- `go`は同じ局面をさらに深く読みます。完了済みの候補順位や、同じ残り深さのノード結果は再利用します。
- 保持ノード数は既定5万。上限に達した場合も5候補の根と読み筋は確保し、細部の保存を減らします。

内部の全ノードで5候補の厳密順位を求める方式ではありません。実際に分析の根となる各局面で5候補を確定し、その候補の探索済み部分木を残します。
新しい根では、まず選ばれた候補の読み筋の続きと残り深さを引き継ぎます。新局面の5候補の比較が終わるまでは `candidates_complete:false` と明示します。

## 実例：5位を指した場合

初期局面を深さ3まで読んだ時点での候補です。単純な駒得評価であり、定跡や実際の優劣の推奨ではありません。

| 順位 | 手 | 評価値 | 深さ | 保持ノードID |
|---:|---|---:|---:|---:|
| 1 | 7g7f | 200 | 3 | 2906 |
| 2 | 1g1f | 0 | 3 | 2 |
| 3 | 1i1h | 0 | 3 | 3 |
| 4 | 2g2f | 0 | 3 | 4 |
| 5 | 2h1h | 0 | 3 | 5 |

5位の `2h1h` を指すと、元の根ID 1 から候補ノードID 5 が新しい根に昇格しました。着手後の根IDも 5 で、部分木を作り直していないことを確認しています。
引継ぎ直後は深さ 2、読み筋は `1a1b 1g1f`。自動追加探索後の完了深さは 3 でした。
詳細な入出力は `results/v0.3/automatic-play.json` に保存しています。

## 読みを正しく引き継ぐための条件

保存値はそのノードの手番側の評価です。詰みまでの距離はノード基準に正規化して保存し、根が変わったときに補正します。例えば1手詰めの候補を指した直後は、相手番の−100,000となり、単純な符号反転の−99,999にはしません。
再利用する値は同じ残り深さに限定しています。深さ2の値を深さ3の確定値として扱いません。境界値は現在のαβ窓で打切りが成立する場合だけ使います。
各ノードは根からの手順に対応します。同じ盤面でも別の手順へ木を合流させず、実際の棋譜を含む履歴を保持して、千日手・連続王手の判定を守ります。
時間・訪問数の上限で止まった場合、候補順位は最後に全合法手の比較を完了した深さのものを残します。未完成の順位は公開せず、完成済みの内部ノードの結果は次回に利用できます。

## 着手後の追加探索：保持あり／新規の比較

固定した3局面について、1・3・5位を指す9条件を各3回、合計27回比較しました。指す前は深さ3、指した後の比較も新局面から深さ3です。両方式とも上位5候補を計算します。
保持ありはその部分木から再開し、新規は同じ初期局面と同じ全棋譜から空の木で開始しました。測定順は交代、実行は逐次です。表の時間は3回の中央値です。親局面を事前に読む時間は含めず、その訪問数は生データに残しています。

27回すべてで、保持ありと新規の上位5候補の手・評価が一致し、読み筋の合法性と末端評価も確認しました。時間中央値は9条件中9条件で保持ありが短くなりました。
訪問数にはキャッシュから答えたノードも含まれます。訪問数の削減率だけでは、合法手生成・評価・ノード確保を省いた効果を表し切れません。
既に行った親局面の計算を再利用する条件での比較です。最初から5候補を求める負担や共有環境の時間変動もあるため、全体の棋力・一定の速度倍率を示すものではありません。
機能検査を併行した最初の試行は `results/v0.3/validation-run/` に残し、表は機能検査終了後に逐次再測定した値を使用しています。

## 使い方と範囲

```bash
make -j2
./build/shogi-lab --session
```

起動後の入力例：

```text
go depth 3
play 7g7f
show
go
quit
```

`play`で継続探索まで自動実行し、必要なら`go`を繰り返して深めます。設定・出力形式は [README.md](README.md) を参照してください。
保持は同一プロセス内です。プロセスを終了してから探索木を復元する機能と、入力待ち中の無期限の背景探索は未実装です。既存のWebアプリへの組込みではなく、C++研究エンジンの継続モードです。
次の研究では、5候補の初回計算の負担と保持する木の容量、再利用できた深さの内訳を調べられます。駒得評価・静止探索に関する前回の課題も残ります。
