# v0.16：固定手数に依存しない選択的探索と、評価仮説の比較

実験日：2026-09-22（UTC）。起点はGitHub mainの完成版v0.15（`04a4f47da71643dc3b01c7e357741690feb71ce1`）。

**目標手数・候補数を固定しない探索を実装し、6設定・384探索と、やねうら王との16対局を実行した。** 学習補正を弱く反映した版は新規局面の着手指標で改善したが、参考区間が0をまたぐ。標準のv0.15 fastを自動的に置き換える判断はしない。

## 1. 何を変えたか

新しい `adaptive` は、時間・ノード予算で止まる選択的なαβ探索。経路ごとに読む費用を積み上げ、費用の閾値を反復ごとに増やす。唯一の合法手、王手回避、王手、取り返し、探索履歴で有望だった手は先へ進みやすくする。低優先の手も候補から捨てず、浅い確認でαを更新すれば通常の費用で読み直す。

全候補を同じ深さまで読む設定でも、上位何手だけを読む設定でもない。ただし時間内に全変化を十分確認できる保証はない。αβカットは残り、静止探索では非王手時の駒取り・成りなどに対象を絞る。

費用を使い切った地点の駒取り・成り・王手回避は、固定の静止探索深さ6で切らず継続する。95plyは再帰の非常停止であり、目標深さではない。到達した場合は未完了反復を破棄する。今回の局面比較は全384探索が時間制限で停止し、非常停止・合法手への緊急フォールバックは0件だった。

発想は実現確率探索と再探索の文献に基づくが、今回の費用は手の性質・順序・オンライン履歴から決めたヒューリスティックで、校正した確率ではない。[根拠と具体的な費用規則](RESEARCH-v0.16.md)。

## 2. 過去の学習から立てた評価仮説

v0.12では、候補差の誤差を小さくしても探索の葉で補正が偏り、探索が膨らんで浅い結果しか返せないことがあった。そこで、保存済みpair100の後段を使って、反映量と上限を分けて実験した。今回は新規の重み学習をしていない。

| 仮説 | 評価 | 狙い |
|---|---|---|
| H0 | 元NNUE | 探索の配分変更だけで改善するか |
| H1 | 元評価＋学習済み評価との差の25% | 過去の学習情報を弱く取り入れる |
| H2 | H1の補正を±80cpに制限 | 大きな補正による外れを抑える |
| 対照 | 元評価＋手番側40cp | 学習情報と単純なバイアスの効果を区別する |

H1/H2は元NNUEの特徴変換と第一隠れ層を共有し、32→32→1の後段だけを追加計算する。重い特徴変換を二重に走らせない。式・丸め・元モデルのハッシュは [モデルカード](models/v0.16/MODEL_CARD.md)。v0.15相当と履歴LMRも比較に含める。

## 3. 同じ時間で選んだ手の良さ

v0.15の16根から、固定seedで教師の有力候補を使い8手ずつ進めた。根の過去試験との完全一致を除外したが、元の戦型系列は共有しており、未知戦型への汎化試験ではない。各設定を0.3秒/1秒で2反復し、順序を回転させ、すべて直列に測定した。

全設定の着手と教師の着手を共通候補集合とし、固定やねうら王の深さ12で再採点した。「候補差」は集合内の最高評価との差で、小さいほどよい。全合法手に対する厳密な損失ではない。

学習25%と上限制限版は64組すべてで選択手が同じだった。評価値まで同一だったのは52組であり、上限処理が常に無効という意味ではない。今回の固定時間・局面集合では、上限の追加による着手改善は確認できなかった。

今回の基準はv0.15と同じ探索に観測カウンタを追加したもの。事後の既知8根・各50,000ノード・2反復では、元バイナリに対する探索時間比は 1.050 だった。同じノードでは着手・評価・PVが一致するが、観測なしのv0.15バイナリそのものとの固定時間比較ではない。この費用もあるため、今回だけで原版に対する棋力向上を主張しない。

## 4. どのくらい深くなったか

全16根・1秒・2反復の平均。最大到達手数は「どこか1本がそこまで進んだ」長さであり、すべての応手をそこまで読んだ保証ではない。採用PVは実際に返した読み筋。

| 設定 | 最大到達手数の平均 | 採用PVの平均手数 | ノード数/探索 | 緊急着手 |
|---|---:|---:|---:|---:|
| v0.15相当 | 13.06 | 5.62 | 445,787 | 0 |
| 履歴LMR | 13.41 | 6.38 | 450,171 | 0 |
| 選択的探索＋元NNUE | 22.94 | 6.47 | 426,646 | 0 |
| 選択的探索＋学習25% | 23.03 | 6.69 | 421,843 | 0 |
| 選択的探索＋学習25%・上限 | 23.16 | 6.44 | 418,531 | 0 |
| 選択的探索＋40cp対照 | 22.12 | 6.56 | 424,182 | 0 |

adaptive の `completed_depth` は4費用単位ごとの反復番号であり、従来版の深さと比較しない。JSONで `iteration_unit` を分け、実到達は `selective_depth`、読み筋はPVの長さで報告した。上位5候補を表示する従来機能は保持し、新ドライバの今回の比較はMultiPV=1（探索候補が1手という意味ではない）。

## 5. やねうら王との実対局

### 最初の反復が終わらない反例

学習25%版の中飛車・自作先手の1局では、77・79・81・83・85・87手目の6回、1秒以内に最初の反復を完了できなかった。各回は確認を終えた7〜48個の根候補のうち最善の合法手を緊急手として返した。これを完了した探索と数えてはいない。他の設定の元の16対局では緊急手はなかった。

この6局面の全履歴を固定し、4設定×1秒で24探索を追加した。結果を見てから選んだ同一対局の反例であり、独立した棋力試験には数えない。

| 同一6局面の再探索 | 最初の反復も未完了 |
|---|---:|
| 従来設定 | 0/6 |
| 選択的探索＋元NNUE | 4/6 |
| 選択的探索＋学習25% | 6/6 |
| 選択的探索＋学習25%・上限 | 6/6 |

従来設定は全6局面で少なくとも1回の反復を完了し、完了深さは2〜4。新版で未完了だった全例は、根の1節点を除く全ノードが静止探索だった。最初の反復では根の手を指した直後に静止探索へ入るため、深さ制限を外した駒取り・成り・王手回避の探索が予算を消費していた。補正上限だけでは解決しない。

**次の優先課題は、候補全体の初回比較を完了させるための計算配分と、途中から再開できる探索。** 固定深さへ戻す以外の方法で、1本の戦術探索が全時間を使い切るのを防ぐ必要がある。この反例を修正済みとは扱わず、新版を標準採用しない理由に含める。[追試24探索](results/v0.16/fallback-replay.json)、[元の緊急手の記録](results/v0.16/fallback-diagnosis.json)。

## 7. 判断と次の改善

- 選択的な深掘りそのものは実現した。読む範囲と停止条件を観測でき、各手の計算配分を記録できる。
- 学習25%は着手品質の平均で良かったが、すべての局面では改善せず、差の区間も0をまたぐ。標準採用を確定するには新しい戦型・開始局面での追試が必要。
- 補正上限を加えた版は今回の局面比較で同じ手だった。H2の追加利益を主張しない。
- 単純な+40cp対照は改善を説明し切れなかった。学習情報の再利用と、単なる評価のかさ上げを分けて記録した。
- 次は反例で「候補を浅くしすぎた」のか「末端評価が悪い」のかを、反実仮想の再探索で切り分ける。評価の揺れと候補間の差を探索費用に入れる仮説を試す。今回の16根は以後は開発集合として扱う。

## 8. 検証と保存物
